# Production QA Protocol

## Purpose

The repository has deterministic source/build checks. This document records the complementary checks that require a deployed site, browser, crawler, or Search Console evidence.

## Automated gate

The GitHub quality workflow is authoritative for deterministic checks. It runs:

- production build;
- design-system smoke test;
- UI architecture smoke test;
- SEO smoke test;
- route-quality audit.

The exact route count is generated by the current route audit; documentation must not hard-code an old page count.

## Production checks

### Crawlability

- `/robots.txt` returns HTTP 200.
- The sitemap URL in robots is reachable.
- Every canonical URL returns HTTP 200.
- Important pages do not unexpectedly redirect across locales or to legacy routes.

### Localization

For every Persian/English pair:

- canonical points to the page itself;
- `hreflang="fa"` points to Persian;
- `hreflang="en"` points to English;
- `hreflang="x-default"` points to the Persian primary representation;
- localized pages reciprocate the relationship.

### Entity graph

Verify rendered JSON-LD uses the stable first-party Person ID:

`https://leilarazavi.github.io/#person`

Check that page-specific entities reference that Person where the visible content supports the relationship.

### Social previews

Verify rendered Open Graph/Twitter metadata for the homepage, About, Publications, Media, podcast series and representative detail pages. Page-specific media should use the page's intended social image rather than an unrelated default asset.

### Performance

Run mobile Lighthouse against at least:

- `/`
- `/about/`
- `/publications/`
- one publication detail page
- `/media/`
- `/media/sohbat-jan/`

Record LCP, CLS, INP, transfer size and major image/font contributors.

### Accessibility

Manually test keyboard navigation, focus visibility, skip link, mobile menu interaction, heading hierarchy, contrast, reduced motion, image alternatives and language/RTL behavior in current Chrome and Firefox.

### Search Console

After deployment, inspect:

- indexed/not indexed pages;
- canonical selection;
- duplicate/alternate canonical reports;
- sitemap processing;
- Core Web Vitals;
- branded queries and exact publication-title queries.

Do not label an indexing observation as a code defect until the reported reason is understood.

## Evidence policy

Every production check must be recorded as `PASS`, `FAIL`, or `OPEN`, with date and URL/scope where applicable. Never turn a source-level assertion into a production PASS without production evidence.
